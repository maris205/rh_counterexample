## 问题、方法与配置

最简单的问题是：从临界线左右两侧出发，是否出现不随提高精度而消失的线外
求根结果？已有记录中的 305 个窗口止于 t=10000；本轮选 t=10010、10012、10014，
每个高度取实部 0.30、0.49、0.51、0.70。原始历史批次不在本机，本轮未重新核验它们。

直接复用 `zero_lab.refine` 的自由实部阻尼 Newton 方法，未向初值提供已知零点位置。
每个初值分别从头运行 50 位、80 位两次求根；对后者以 mpmath 和 python-flint/Arb
交叉核对函数值。每档至多 40 步，每任务硬超时 90 秒。Newton 高度允许变化，
搜索轨迹只受 0 < t < 10050 与 0 < sigma < 1 的既有限制，初值区间并非覆盖区域。

先执行两个 35/50 位 smoke 子任务，并在第一个完成后主动暂停；恢复时只执行第二个，
第一个 JSON 的 SHA-256 保持不变。主实验起点已事先固定，不根据 smoke 结果修改。

原要求的 Python 3.10 不可用，实际使用 Python 3.14.3；NumPy 2.5.3、SciPy 1.18.1、
mpmath 1.4.1、python-flint 0.9.0 均可用。

## 有限数值结果

| 起始高度 t | 起始实部 sigma | 最终数值高度（约） | 吸引到该端点的任务数 |
| --- | --- | --- | --- |
| 10010 | 0.30 | 10010.396260197881 | 1 |
| 10010 | 0.49、0.51、0.70 | 10010.859145158247 | 3 |
| 10012 | 全部四个实部 | 10012.098374860015 | 4 |
| 10014 | 全部四个实部 | 10013.836810490507 | 4 |

- 两档精度的端点最大距离约 `2.8112e-37`，低于预设 `1e-25` 阈值。
- 80 位结果的最大实部偏离约 `3.3662e-74`；最大 ζ 残差约 `9.4045e-73`。
  这些是数值计算结果，不是实部恰等于 1/2 的严格证明。
- 12/12 个 mpmath 与 FLINT 函数值核对一致；所有父进程及子任务 stderr 日志为空。
- 没有精度不稳定、未收敛或跨库不一致的待复核条目；没有新的线外数值候选。

本轮保留的具体方法学观察是：在 t=10010，同一高度仅改变初始实部，就进入两个
不同零点的吸引域。这不是 RH 异常证据，但说明求根结果依赖初值，不能把少量种子的
收敛结果理解为已枚举附近所有零点，也不能将两侧初值当成独立统计样本。
