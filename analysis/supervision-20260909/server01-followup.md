# server01 标记窗口后续复核（2026-09-10）

本报告只追加独立复核证据，不改写 `runs/server01` 中的原始终态文件。

## 输入与方法

- 原始 `RESULTS.json` SHA-256：`944f2bfe5bf500b501293a1ddd2f3309113b2e7aad27a82d9c9ecd0e7d4cdc25`
- A_min 窗口文件 SHA-256：`bb78d21b4499cc060dd137b7032e833505b22a86db5d02b349447775274c346d`
- B_max 窗口文件 SHA-256：`b6f895038161b063e86238e48878a36cda90e141a333924516cd145fef9a4fb9`
- Arb 复核实现 `zero_lab.py` SHA-256：`d67ee1c7d4d1389af9e05e0c129a81aa96287531d085ce16cc0978f93bdbe360`
- Python 3.12.3、mpmath 1.3.0、python-flint 0.8.0。
- mpmath 使用 50 位十进制精度计算四个原始窗口点。
- Arb 使用 100 位十进制精度，对每个点的两个坐标同时取半径 `1e-9` 的闭矩形，调用 `acb.zeta()` 做整盒包围。

四个点的 mpmath 实部和虚部均与原始 Arb 80 位中点一致到约 30 位。原始
`1e-8` 半径盒分别给出 `INCONCLUSIVE_VALUE_ENCLOSURE`，原因是高高度区间传播过宽；
把半径收紧到 `1e-9` 后，四个局部盒均排除了零。

## 解释范围

这项复核排除了两个标记窗口中心点和最佳点附近半径 `1e-9` 的闭矩形中的 ζ 零点。
它没有证明整个搜索窗口无零，也没有进行整个窗口的矩形零点计数，因此不能改变原始
运行的 `NEEDS_CHECK` 状态，更不能构成 RH 反例证据。原始运行文件保持不变，便于按
其记录的 `1e-8` 小盒参数复现；本报告是追加的局部复查结果。
